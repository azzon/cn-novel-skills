## 攻击1: G5跨章查重门(18字shingle, >15% FAIL / >8% WARN)

### 攻击设计
取既有章(沙箱中第078章),构造四种"洗稿"变体,用gate_chapter.py同款shingle算法(18字窗口,空白剥离,集合交/新集合大小)测最坏相似度。

### 实测数据

| 变体 | 内容 | 最坏相似度 | 判定 |
|------|------|-----------|------|
| 原文自比(上界校准) | — | 100% | FAIL(门对纯复制有效) |
| 全局同义词替换(24词表:说→道/他→那人/现在→此刻…) | 全文词级改写,情节逐拍一致 | **39.1%** | FAIL(抓得住) |
| 同义词+70%句子首尾子句换位 | 情节节拍1:1 | **1.2%** | **PASS→穿透** |
| 每17字插1字"很" | 5.9%字符变异,内容94%原样 | **0.0%** | **PASS→穿透** |
| 每10字插1字 | 10%变异 | 0.0% | PASS |
| 拼贴victim原句5%-20%进大章 | 混入原句 | 1.0%-3.7% | 全PASS |

随后把"同义词+子句换序"版作为新章第080章跑真实gate: G5无任何输出行(连WARN都没有)。

### 暴露的盲区(确认)
G5本质是**复制检测器**:18字连续完全一致才计入。它抓"抄写",完全不抓"复述"——
- 词级换写+子句重排(洗稿的标准手法)即归零,情节节拍可以1:1;
- 最低变异密度≈1/17字符即可让全部shingle死亡;
- shingle集合语义+分母稀释使"拼贴20%原句"也只有2.1%;
- 无任何节拍级/结构级(句长序列、对话占比序列)指纹。

## 攻击2: G4卷归属门 + .progress.json

### 前提修正(比题目假设更糟)
G4**不读**.progress.json。`gate_chapter.py:113`: `volumes = scan_volumes(files + staged)`——门时刻从文件系统实扫,且**staged文件自身参与区间计算**。因此"区间本身错时门是否放行"的正确答案是:区间由放谁决定,自洽循环。

### 穿透1: 最早卷吞并(实测)
第090章.md(1600字独立文本)放入text/卷1/:
```
=== gate_chapter [第090章.md] PASS ===
```
机理: 卷1区间实扫为[1,90],expected_volume(90)按卷号升序找第一个包含者→卷1;act=卷1→放行。**任何新章号放进最早卷即可吞并全书编号空间**,outline里卷4[74,79]形同虚设。

### 穿透2: 影子卷(实测)
text/卷04/第081章.md(注意"04"零填充,parse_vol生成独立键"卷04"):
```
=== gate_chapter [第081章.md] PASS ===
```
且沙箱内--recompute输出:
```
[progress] max=81 next=82 volumes={'卷1':[1,30],'卷2':[31,50],'卷3':[51,73],'卷04':[81,81],'卷4':[74,79]}
```
派生缓存被污染:出现第9个"卷",next_action错误。

### G4还能拦什么(诚实记录)
- 章号落在早期卷max之后却放进更晚卷(如055→卷4,被卷3[51,73]先包含)→FAIL;
- 卷目录非数字(卷A)→act=None→FAIL;
- 附带实测到一次语义混乱的误报: 同批staged 090(卷1)时,080→卷4被判"应属卷1"——两章区间互相污染,门语义依赖staged顺序。

### progress.json自愈顺序推演(实测)
- hook第28-31行: CHAPTERS与SKILLS_STAGED皆空→**早退**。篡改.progress.json(max=999/卷区间互换/伪造story_time)后**单独staged**: 输出"[PASS] 无章节/技能变更,跳过",真实commit入库,入库内容max_chapter=999(沙箱commit 7ed822f实测)。
- 带章节staged时: 重算在hook第127行(D步),位于所有门(A/B/C)之后;且门根本不把progress当输入→"重算发生在放行之后"成立,但因它非门输入,对放行无影响;自愈发生在本次提交内,但两次提交之间,消费progress的技能(continuation/pipeline-chapter)读到的是被污染指针。

## 攻击3: waiver登记制

### 粒度结论
**章级**。一行`- chNNN:`同时豁免: check.py全部34项(hook 77行)+场景卡门(91行)。**不**豁免韧性门G1-G5(gate_chapter无waiver入口)——所以不是"全门免检",但attack面已足够大。

### 端到端实测(真实commit)
1. 自助登记: `echo "- ch082: 红队测试豁免(不需要任何审批人签名) (2026-09-11)" >> ledgers/waivers.md`——登记本身零门(hook对ledgers/无检查,单独staged时早退)。
2. 构造12项FAIL章节(禁词眼神闪过/空气凝固、禁句、破折号5处、情绪告知、自评词、章内重复5处、对话占比1%、英文hello world、时代错位"手机"、"如你所知"设定伪装),对照裸跑: `check.py exit: 1`(12条FAIL)。
3. staged后hook输出:
```
[WAIVER] check.py豁免(登记制)
[WAIVER] 无场景卡(已登记)
✅ 质量+流程+韧性门通过  (exit 0)
```
4. `git commit`真实落库(沙箱commit 5b0ad29),commit-msg"第082章 红队豁免测试(垃圾内容)"同时证明msg门内容盲。

### 边界
- 正则`^- ch0?082:`: "- ch082:"与"- ch082"变体命中(同章等价);"- ch0820:"不会误豁免ch082(无前缀碰撞)。
- 防御余量: 即便有waiver,G1(<1500字FAIL)/G5/G2/G3/G4照跑——攻击者仍需≥1500字与既有章<8%重叠的文本,对"垃圾但新鲜"的文本无约束力。
- 已登记的ch041/ch043为**永久**豁免: 今后对这两章的任何修改都免34项检查(无过期机制)。

## 攻击4: commit-msg门方向性 + 字数 + 逃逸

### 拦住的部分
- 方向性反问"提交080写999信息": 被拦——msg门遍历**staged**章号,staged含080而信息无"第0?80章"→exit 1。方向其实是"信息必须认领文件",不是"文件必须匹配信息"。
- G1字数硬底线实测全拦: 13字→FAIL、1字→FAIL、空正文+30字超长标题→FAIL(标题#行不计入正文,0字)。100字新章同样拦。

### 穿透的部分(实测)
1. **大写扩展名逃逸**: `text/卷4/第087章.MD`——章节正则`第[0-9]+章\.md$`不匹配→hook早退"无章节/技能变更,跳过"→未过任何门入库(gate_chapter的glob`第*章.md`同样无视,progress也不计)。
2. **删除免检**: STAGED_ALL用`--diff-filter=ACM`(18行,无D)→`git rm text/卷4/第079章.md`→"跳过"→入库。删整卷/删书零阻力。
3. **组合拳**: 删第079章.md+新增第079章.MD(垃圾)=无门换血,progress还会把该章从统计里抹掉。
4. 内容盲: 只要有waiver(攻击3),1500字新鲜垃圾+信息写对章号,全链绿灯(commit 5b0ad29即此形态)。

## 攻击8: check.py第34项 vs 全角引号U+FF02(实测)

## 剩余最大攻击面排序(按风险×当前无防护)

1. **删除/改名/大小写逃逸**(ACM无D + `\.md$`大小写敏感): 章节可无门换血/抹除,连progress都会配合抹掉统计——修复成本几行,危害最直接。
2. **waiver自助化+章级全免**: 一行登记=34项质量门+卡门免检,无审批人、无过期、waivers.md自身无门、已登记章永久免检。
3. **G4自洽循环+progress单staged早退**: 卷结构可静默重写(吞并/影子卷),派生缓存可单独入库。
4. **G5复述盲区**: 5.9%字符变异即归零;情节复述完全免疫(修复成本最高,排后)。
5. **skills运行时域入口零校验+整树删除静默**: 运行时路由可被劫持而体检报全绿。
6. **场景卡空壳**: 存在性门,内容零校验。
7. **U+FF02低剂量引号**: 34项单字符盲区。
8. **G6无强制**: 设计内(待硬化),但账本格式已可解析,硬化成本低于预期。

结构诚实声明: 全部门是客户端hooks——`--no-verify`或未安装即全免。威胁模型只能是"自我纪律护栏+防LLM手滑",v4若要硬保证需pre-receive/CI复制关键门。

## v4加固清单(按性价比排序)

### P0(每项数行-数小时,堵的都是实测穿透)
