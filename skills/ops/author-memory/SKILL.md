# author-memory:作者记忆(ops域)

> 溯源:oh-story author-memory协议(三库中最完整的基础设施——我们的体系管书不管人,此技能补位)。产物:`ledgers/作者偏好.md`。

## 流程

**1 捕获判定(先判该不该记)**
1.1 **记**:用户明示偏好("以后章节名都用这个风格")/重复纠正(同类纠正≥2次,升为偏好)/明确授权的推断;
1.2 **不记**:一次性执行指令("这次"字样=只执行)/助手自产的文字(禁自我学习)/故事事实(走ledger)。

**2 偏好管道(三级,置信递减)**
- **active**:明示偏好,立即生效;
- **pending**:重复纠正与推断——下次写作时**提示用户确认**("你上次纠正过X,是否立为规则?"),确认升active,否认记forget;
- **forget**:明确否决的偏好,留存防重犯(写作时反向提示"用户已否决X")。

**3 作用域四级**
book(本书)/genre(此类题材)/workflow(流程偏好)/global(全部)——每条偏好标注作用域,注入时按当前任务取最小适用集。

**4 注入与体积**
4.1 按任务类型注入(scene-card时注入文类偏好;audit时注入流程偏好);**注入量≤2KB**;
4.2 冲突处理:新偏好与旧冲突→旧标superseded(留档),不静默覆盖;
4.3 回执:重大偏好生效后,在产物头部注"依用户偏好#N"——可追溯。

**5 复盘钩子**
每卷末:pending区清零(全部确认或否决);偏好库与风格包/宪法冲突检查(冲突→skill-sync裁决)。

## 闸门

捕获判定过/三级不混/作用域齐/注入≤2KB/superseded留档。

## evals

- "以后别用这种开头"(→重复纠正→pending→确认升active)

- "我记得说过不要…"(→forget反向提示验证)
