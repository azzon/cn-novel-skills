# style-compiler:风格包编译

> 溯源:docs/20(文笔论/三层模型)·23(语言层规格)·26(锚定校准/盲评协议)·迭代31实战。产物:`story/50-风格包.md`。

## 前置条件

`story/audit/立项预审-<日期>.md(取最近一份)` 已过用户卡点(立项通过);锚样本已选定(同赛道公认佳作的开篇章,可公开阅读的免费章节)。

## 流程

**1 拆锚**
1.1 取锚样本1-2章,产出工艺拆解:节奏数据(段落长度分布/对话占比)/笑点逐个解剖(位置/类型/铺垫拍数/句末落点)/可模仿特征清单≥20条(句法级,附短语级微引用)/开篇五行与结尾五行逐行分析;
1.2 特征清单转为本项目可执行的**风格卡**(≤200字:断言句开场/降格补刀/段1-2句/松段配额/警句限额/禁项/**喻体域**——锚人物的职业与生活经验域清单,活喻的喻体必须落在此域内,红队20260919文笔批)。

**2 自写范例段**
2.1 按场景型各写一段范例(日常/争辩/揭示各一,每段350-600字),用本项目的题材与人设,**逐条套用第1步特征**;
2.2 范例三禁自查:无gloss/无时代错位词/无预告片腔(docs/20)。

**3 盲评校准(不过不收)**
3.1 范例段与锚样本摘录成对(随机标记为A/B),交**干净上下文**的评审代理盲评——**操作SOP**:开一个新子代理(Agent tool/subagent),人设设为"毒舌读者",prompt里只贴A/B两段文本+评审指令(哪段更好笑/更自然/引句证明),不给任何项目文件路径——这就是"干净上下文";
3.2 判定:范例在笑点密度与自然度上**不输锚**方可收;输了→按代理逐条意见修订范例,重评(至多两轮;仍输→换锚或改风格卡);
3.3 评审中的改进意见(如"段尾必抖机灵是卖巧税")回写风格卡。

**4 落盘与接口**
4.2 产出物:`story/50-风格包-v<N>.md`(版本号递增,头部注明生效章节区间,旧版不删;劣稿锚**必须内嵌样张原文**(约300字摘录),不可只放指针——指针会死链,死链=锚定校准裸奔)(风格卡+范例段+盲评记录+锚样本出处+**劣稿锚附录**——首批冷启动用盲评记录中得分最低的旧稿充当,供reader-proxy锚定);
4.5 **双质检**:voice test(只读风格包能否写出作者认的声音)与brevity test(需开着范例写=过度规定,删规定留原则)。

4.6 **拆分与分录**:风格文件按场景型x人物拆条目(写谁注入谁);Patterns(想复现)与Problems(无意识tic,频次判据)分录。

4.7 使用接口:scene-draft 的五件套注入第一件即本包中与场景型匹配的范例段。

## 闸门

拆锚特征≥20条且句法级/范例三段齐且三禁过/盲评不输锚/风格卡含禁项与松段配额。
