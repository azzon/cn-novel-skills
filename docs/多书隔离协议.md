# 多书隔离协议

> 教训来源：2026-09-13 开新书《法医秦见微》时，新书前提/声口卡/卷一纲/场景卡直接覆盖了主书《重生2005》的 story/ 依据层和 text/卡/，导致旧书依据丢失（已从 git 恢复）。本协议保证同类事故不再发生。

## 1. 目录布局

```
仓库根/
├── story/  text/  ledgers/  docs/  tools/   ← 主书《重生2005》专用（历史占用，45章+工具链已绑定）
└── <书名>/                                   ← 每本非主书一个独立书根
    ├── 00-前提.md  01-主题.md  世界设定.md
    ├── 卷一纲.md  声口卡.md
    ├── 卡/          ← 场景卡（text/卡 等价物）
    ├── text/卷1/    ← 正文
    └── ledgers/     ← 该书自己的台账（开写前建）
```

## 2. 铁律

1. **非主书的一切产物不得写入仓库根的 story/、text/、ledgers/**。写错位置=污染主书依据层。
2. **开新书第一步**：`mkdir <书名>/{卡,text/卷1,ledgers}`，所有立项件直接落在书根内。
3. **门与检查工具一律吃显式文件路径**（`check.py --modern <file>`、`gate_chapter.py <file>`），天然多书兼容；禁止写死主书路径的新调用。
4. **台账/流水/时间线工具在书根内运行**：ledgers/、.progress.json 按书隔离；`pipeline_runner.py`/`evals.py`/`structure_check.py` 当前为主书专用，跨书使用前须先参数化书根。
5. **卷号命名带书感知**：新书卷1 的卡/章节在书根内自成 `卷1`，与主书 `text/卷1/` 互不可见。

## 3. 开新书标准动作（接 workflows/book_design.yaml）

1. `premise-fit` 五维闸 → 通过后才建目录
2. 建 `<书名>/{卡,text/卷1,ledgers}` + 六件套（前提/主题/世界设定/卷纲/声口卡/风格包）
3. 逐章：卡→稿→check→gate→该书 ledgers 盖章→commit（commit-msg 钩子按书名正则放行，见下）
4. 每书独立 `scores.json` 与质量基线，禁跨书混算

## 4. commit-msg 钩子

钩子按 staged 文件路径判断书：主书章节文件要求提交信息含 `第0*N章`；非主书书根内的章节要求提交信息含书名或 `第0*N章`。混提主书+新书时两者都须满足——**建议新书与主书分开提交**。

## 5. 事故恢复

若再次发生覆盖：`git log --oneline -5 -- <被覆盖文件>` 定位最后正确版本 → `git show <commit>^:<file> > <file>` 恢复 → 三门复验（check/gate/structure）→ 提交并在信息中注明"恢复"。
