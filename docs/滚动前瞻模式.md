# 滚动前瞻混合模式（200万字长篇生产协议）
<!-- 红队20260919: 用户方法论问题的系统级落地 -->

## 核心答案

**不是纯瀑布（先搭完900章大纲再写），也不是纯逐章（一章一章即兴）。**

是**滚动前瞻**：每层只往下看一层，每层完成后回头修正上一层。

## 为什么纯瀑布会死

- 900章大纲=10万字——还没开写就先写了一本书
- 网文是连载，读者反馈应影响走向
- 角色会在第50章"活过来"，做你没计划的事
- 第300章时第1章的设计已不适用

## 为什么纯逐章会死

- 400万字无结构=伏笔堆积不回收/人物漂移/节奏崩溃
- 第800章记不住第50章的细节（压缩记忆有极限）
- 读者回看"越写越散"

## 五层结构

```
第一层·全书骨架(一次性,写前锁死)
  前提句/人物弧线/终卷答案/四卷大结构/名场面钉桩
  → agent_storm premise(全5波×10=50 agent红蓝对抗)
  ↓
第二层·卷纲(每卷30章,写前1卷锁死)
  本卷问题句/冲突升级/三峰位置/伏笔埋收计划
  → agent_storm volume(全5波)
  ↓
第三层·前瞻章窗(写前5-10章的场景卡,不更远)
  场景卡细化到beat,但只做5-10章(留即兴空间)
  → agent_storm design(全5波,对每张卡)
  ↓
第四层·逐章写作(每章全5波风暴)
  卡→bundle→写→50 agent风暴→修复→归档
  → agent_storm chapter(全5波)
  ↓
第五层·卷末复盘(每30章一次)
  arc-review连读→哪些没做好→重排下一卷纲
  → agent_storm periodic(全5波)
  ↓
  回到第二层,滚动下一卷
```

## 关键纪律

1. **前瞻窗口=5-10章**：场景卡只做5-10章，不做更多——保留角色即兴权和读者反馈调整权
2. **卷末重排**：每卷结束后，下一卷纲**根据本卷实际情况重写**（不是死守总计划）
3. **骨架不动的底线**：前提句/终卷答案/人物核心弧线在第一卷锁定后不再改（除非红队判定致命伤）
4. **每层全5波**：设计文件/卷纲/场景卡/正文/复盘——所有产出物都过50 agent红蓝对抗

## 与纯瀑布/纯逐章的对比

| | 纯瀑布 | 纯逐章 | 滚动前瞻 |
|---|---|---|---|
| 全书结构 | ✅ 锁死 | ❌ 无 | ✅ 骨架锁死 |
| 灵活性 | ❌ 死板 | ✅ 完全灵活 | ✅ 卷级灵活 |
| 伏笔管理 | ✅ 预设 | ❌ 堆积 | ✅ 卷纲排期 |
| 角色成长 | ❌ 预设轨道 | ⚠️ 可能漂移 | ✅ 卷末校正 |
| 读者反馈 | ❌ 无法响应 | ✅ 即时响应 | ✅ 卷级响应 |
| 400万字可行性 | ❌ 大纲即一本书 | ❌ 必然崩溃 | ✅ 工业化可行 |
