# 商业质量线（发布门槛定义·商用生产）

> 定位: 本系统此前只定义了"过门"(FAIL=0 的工程线),从未定义"可发布"(读者肯付钱的商业线)。
> 两线分离: 工程线拦烂稿,商业线决定这一章/这一卷能不能拿去卖。

## 单章发布线（每日更新口径）

| 维度 | 门槛 | 判定者 |
|---|---|---|
| 工程线 | check/gate/voice/card 四门 0 FAIL, WARN 全处置(修或waivers登记) | 机器 |
| 冷读 | ≥8/10 且**拉力判据过**(代理能一句话说出读者憋着的问题) | 冷读代理(锚定有效前提) |
| 致命问题 | 冷读列出的弃书级问题 = 0(修完复冷读) | 冷读代理 |
| 质量分 | ≥ 本书题材线(见 `<书根>/题材配置.md`,默认70) | quality_score |
| 期待链 | 在充能 ≥2 条(下一章有非读不可的引力) | 爽点管道账 |

任一不过 → 该章不进发布队列,回修订。

## 上架线（付费卡点·卷级）

- 存稿 ≥30 章(日更30天缓冲,防断更=商业死亡)
- 黄金三章复验: 冷读均 ≥8 且死局/金手指首付/爽点首付三件套全过(golden-opening+opening-arc 验收)
- 章王在位: 上架前 5 章内至少 1 章冷读 ≥8.5(付费转化点有硬货)
- 书名+简介终审(positioning 技能,书名记忆度自查)

## 反馈回路（发布后·此前完全缺失）

- `ledgers/读者反馈账.md`: 追读/弃书点(评论原文+章号)/付费卡点转化/催更主题
- 周复盘: 反馈账 → 修订排期(revise 域路由) + 爽点管道校准(读者要的爽没给/给的爽没人要)
- 月度市场复扫(market-scan 重跑): 对标漂移检查——本书卖点是否还在赛道上

## 产能纪律（商用吞吐）

- 每章全流程成本记录进 `ledgers/生成记录.md`(迭代轮数/冷读次数)
- 日更轨: 机器门全开 + 冷读抽检(每 5 章全量冷读,其余章快评:拉力判据+致命问题二项)
- 精品轨(卷首末/章王): 全量冷读 + alt-takes 多方案必走
