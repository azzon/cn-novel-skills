# 活文档协议（文档三层生命周期）

> 来源: 拉力审计教训——法医书立项漏人物引擎(ghost/want从未定义)且设定文档写完即死,不随剧情进化。
> 原则: **设定不是写完就归档的石碑,是随故事生长的活物**。每份文档必须声明自己的生命周期层。

## 三层生命周期

| 层 | 性质 | 变更时机 | 责任技能 | 例 |
|---|---|---|---|---|
| **恒定层** | 立项锁定的骨架。改动=重大决策,须登记理由 | 仅重大转折(卷末/书主指令) | premise/theme/char-bible | 主角Ghost/Wound/Lie/Want/Need、世界观根本法则、主控思想 |
| **演进层** | 随剧情推进而更新、披露、演化的活内容 | 每章归档时(ledger-update)/每卷末(character-audit折叠) | ledger-update/character-audit/canon-update/foreshadow-plan | 人物当前状态/关系位移/伤疤累积、世界信息的披露进度、伏笔状态 |
| **派生层** | 从正文+账本可随时重建的缓存 | 机器自动重算 | rebuild/gate --recompute | .progress.json、scores.json、章摘要、时刻卡 |

## 各文档的生命周期声明

| 文档 | 恒定层内容 | 演进层内容 |
|---|---|---|
| 人物圣经 | Ghost/Wound/Lie/Want/Need/压力反应/弧光方向 | 当前状态/关系位移/伤疤与认知变化/已披露背景清单 |
| 世界设定 | 根本法则/力量(能力)体系边界 | 时代事件的披露进度/新增野设定(canon-update回流) |
| 主题档案 | 主控思想/道德论证网 | 两难实例的累积(每卷实际演过的两难) |
| 00-前提 | 前提句/设计原则 | —(恒定) |
| 卷纲 | 单元序列(骨架) | 执行状态标记(哪些按纲/哪些偏航及原因) |
| 台账(八账) | — | 全部(纯演进) |

## 机器强制点

1. **system_readiness 设计完整性**: 书根必须存在人物圣经且含引擎字段(Ghost/Want等)、线弦账首条=欲望线——缺=🔴先修再产。
2. **ledger-update 八账**: 每章归档时除八账外,同步人物圣经**演进层**的"当前状态"(与人物状态账同源,人物状态账是演进层的机器可读形态)。
3. **character-audit 卷末**: 对照恒定层查弧光推进+把演进层折叠为"卷末快照"(追加,不覆盖历史快照=人物成长的时间线)。
4. **披露排期**: 人物背景/世界信息的披露是排期行为(什么读者在何时知道),在人物圣经"披露进度"区登记,防一次倒完或永不见天日。

## 更新纪律

- 演进层更新禁手写重建: 从本章正文提取(rebuild原则),由 ledger-update 流程执行
- 恒定层变更必须在 git commit 信息中注明"恒定层变更:<字段>"
- 文档冲突时: 正文 > 演进层 > 恒定层(故事是第一现实)
