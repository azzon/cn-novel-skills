# 红队报告: 长跑稳定性(300+章/多卷/跨年无人值守)

> 2026-09-15。靶标书: 1993南下的船票(32章/2卷在写)。方法: 实测账本体量+bundle实跑+沙盒复现, 不空谈。
> 结论先行: **性能不会崩**(gate 0.05s/check 0.09s@32章, 300章线性外推仍在亚秒级); **会崩的是记忆通道的方向性缺陷**——三个槽位现在就在空转, 两个折叠/裁剪规则与读取协议方向相反。

| ledgers/ 全部17本 | 344行/68KB | 若线性 ~3200行; 有折叠的4本不缩反增(见§2) |

## 1. 注入预算: 三个槽位现在就空转, 修好就会爆

实跑 `pipeline.py bundle 32 --book 1993南下的船票`:

| 槽位 | 实占/上限 | 诊断 |
|---|---|---|
| 8伏笔在跑项 | **0**/2600 | 过滤正则`状态.*(养|悬空|待回收)`与1993伏笔账实际词表(**充能/卷二引信/终卷兑**)不匹配 → 13条在跑伏笔**从不注入**, F-3三年之约挂账300章也进不了生成现场。"养"义务全靠模型自觉 |
| 3声纹行 | **0**/400 | 解析器只认markdown表格行(`\|`开头), 1993声口卡是`## 人名`+`- 字段`格式 → 禁词/口头禅**从不注入**(voice_check门事后能拦部分, 生成现场裸奔) |
| 7圣经 | 263/1500 | 只装"全书卡(**1993不存在**) + 当前卷摘要" → **前卷摘要永不注入**(见§3) |
| 10生活素材 | 719/1200 | MATERIAL回退主书`story/素材库.md`=**《重生2005》电子城素材灌进1993模具厂**(跨书污染, 活体bug, 见§6) |
| 2场景卡 | 1251/1600 | crop为`t[:cap]`保头裁尾; 卡骨架Pre/Post/**Forbid在尾部** → 富卡超限先裁禁忌 |

**死结**: 空转槽修复(伏笔词表+声纹格式+全书卡)与预算上限互斥——满配=634+500+1600+400+1800+900+1400+1500+2600+550+500+1200+400=**13384 > 10200硬上限**。当前6418的"健康"是三个记忆槽失血的假象。修记忆=爆预算; 不修=失忆。槽8伏笔在300章规模(Z级3-5条+A级每卷8-12条)将独占1200-2800字, 单槽吃掉1/4预算。

**超限行为**: >10200时bundle return 1(磨刀十五批后为硬FAIL, 好——但无人值守=停机等人, 且归档手段只有4本账的折叠, 折叠本身有§2的方向性bug)。

## 2. ledger_compact: 折叠方向与一切读取协议相反(沙盒实锤)

`keep_tail`把旧行移到文件**尾部**归档区(时间线保留60/钩分布60/生成记录120; 伏笔fold同理)。但全系统所有"近窗"读取都是**取尾部=取最新**:

- `gate_chapter.recompute()`: `for l in reversed(lines)`取最后一条`- 第N章|` → story_time
- `bundle`槽9: `read_text(钩分布, -250)` / `read_text(类型轮换, -250)`
- `bundle`槽12: `read_text(口碑账, -450)`

**沙盒复现**(90条时间线跑ledger_compact后):
```
折叠前: story_time来自第090章; tail-reader(-250)读到第[088,089,090]章
折叠后: story_time来自第030章(!); tail-reader(-250)读到第[028,029,030]章(!)
```
periodic.yaml的gate断言"recompute/gate时序取末条不受影响"**不成立**。首次触发在第60-70章(时间线每章1条, >60条后的第一个periodic周期)。

后果链: 钩/类型"近窗"注入的变成**开卷期最老的钩形态** → 防同构/钩轮换的参照系错乱 → G9开场型门与"形态与上两章轮换"指令对着干 → 同构或误判复读。且归档行不删(90→94行), 对整读账本(人物状态/口碑账/技能执行记录, 均无折叠规则)**体量完全不缩**——防膨胀的目标落空一半; 人物状态.md的折叠在docstring里承诺了但main()根本没实现。审计线索方面: 归档仍在文件内+git历史, 线索不丢, 但账本语义先坏了。

## 3. 记忆衰减: 跨卷=失忆(结构性, 非维护性)

跨卷记忆的全部通道盘点:
1. **全书卡**: `圣经/全书卡.md`不存在 → 通道0
2. **前卷摘要**: bundle只读当前卷的`卷N章摘要.md` → 卷3开卷(约第71章)起, 卷1的蔡工线/龙四海恨史/三年之约锚点**没有任何注入物**
3. **人物圣经演进层**: 不进bundle(只做done对账) — 且008-030断更23章的机制性原因正是: 早期done无H5机器门, 靠自觉; 现在有了按章断言, 但`revise/post`模式降级为WARN, 且只查"章号在文本中"(补一行空壳即过, 不查内容), 断更根因(维护是纯人工动作、无脚手架无自动化)**未根治**, 只是装了报警器
4. **当前时刻卡**: 249字, 手动维护, 上限1400 — 唯一跨卷活记忆, 但它是快照不是历史, 且done 6.5新鲜度只WARN
5. **伏笔账**: 见§1, 恒0注入

"近窗+卷摘要"机制在单卷内成立的前提是卷摘要≤1500字; 实测每章摘要124字起(032行比031行长50%, 情节越复杂越长), **第37-55章间卷2摘要超限, `crop(t[:1500])`保头裁尾 → 从超限那章起, 注入的卷记忆永远停在卷初前几章, 最新章摘要被静默丢弃**。evals的`bundle_cropped`冒烟检测写死跑`bundle 2`(第2章, 卷1摘要彼时只有2章量) → 永远抓不到当前章的裁剪。

## 4. 漂移累积: 滚动基线吞噬慢漂

- `evals record`每10章重录(periodic phase_every_10) → 基线=最近状态; 报警条件`base_avg-cur_avg>5`在滚动基线下, 每期跌4.9分**永不触发**。温水煮蛙的数学保证。
- 增量check模式只复验基线头尾各3章+新章 → 中间章恶化盲区。
- drift-audit是type=agent步骤(软约束); 漂移审计-第1期的参照基准已是第1-10章的实测值, 自此每期都在和"上一锅温水"比。
- anchor_recal(劣锚重打分)方向正确, 但同属agent自觉步骤, 且依赖冷读持续产出——**冷读覆盖当前仅34%**(11/32, 软门), 冷读稀疏还连锁断粮范例段飞轮(harvest依赖冷读"最强段落摘录"栏), 风格自喂机制同步停摆。
- 唯一锚死不动的参照: check.py机器规格与PREFIX — 它们抓的是硬指标, 抓不住"警句密度从0.8缓慢爬到1.9/场景"这类规格内的缓慢劣化。

## 5. 状态一致性: 中断重入

- **无原子写**: ledger_compact/scores/progress/各账本全部直接`write_text`覆盖(无tmp+rename) → 断电=半写文件。git兜底, 但恢复粒度=上次commit。
- **中间态组合**: 正文写了账没记(hook D0.5只拦4/13账: 钩分布/时间线/数字账/人物状态——伏笔/梗/线弦/口碑/爽点管道等不拦); 账记了正文没写(ledger_stamped只查章号字样, 不查正文存在); **commit步骤的勾选永远发生在commit之后** → 每章存在"未勾窗口", 而done 6.95查的是**全库聚合勾选率** → 任一章任一项漏勾, 阻塞**所有后续新章**的done(problems硬拦)。无人值守下这是死锁点(chapter_production.yaml的磨刀十五批降级规则只覆盖check不过, 不覆盖勾选欠账)。
- scores命令尾部`bundle_log(n, total)`引用未定义变量, NameError被except吞掉(死代码, 无害但说明此路径无测试覆盖)。
- rebuild兜底评估: 手稿权威可重导13账, 但**口碑账/爽点管道/知情状态是隐性信息**, 从正文重建成本高且有损; 当前时刻卡无机器重建路径。

## 8. 修复优先级(按崩坏先后)

1. **P0(第37章前)**: bundle槽7改尾部优先+卷摘要压缩触发; evals冒烟用当前章号 — 否则卷2中段开始每章都在失忆。
2. **P0(第60章前)**: ledger_compact归档方向反转(归档上移或出文件)+折叠后自检 — 已沙盒复现, gate断言本身是错的。
3. **P1(卷3前)**: 全书卡强制存在+伏笔注入词表对齐+声口卡格式兼容(或统一为表格)。
4. **P1(并行前)**: 素材库跨书隔离(缺书素材库应FAIL而非回退主书)。
5. **P2**: 勾选门按章块化; evals创始基线冻结; 账本原子写。

> 一句话总判: 这套系统的机器门在"拦住坏产物"上很硬, 在"记忆往哪边流"上全是软肋——裁剪裁尾、折叠折叠到尾部、近窗取尾, 三个"尾部"各说各话, 长跑死于此, 不死于性能。
