## 二、P0修复: provenance最小方案(三条,均为机器门)

设计原则: 不要求密码学完美,要求**伪造成本从"打一行总分"涨到"必须真的读过正文且无法复用旧报告"**。

### 2.1 verbatim摘录绑定(杀实验B/D)

报告内`>`引用行/`摘录`行≥3处,每处(去空白归一后)必须在被评章正文原样存在。少一处=FAIL。

```python
# tools/coldread_gate.py <章文件> <报告文件>  —— done第5步与hook D0.5共同调用
import re, sys, pathlib, unicodedata
def norm(s):  # 去空白/全半角归一
    s = re.sub(r"\s+", "", s)
    return s.translate(str.maketrans("：（）：；，", "::();,"))
def quote_gate(chapter_fp, report_fp, min_quotes=3):
    body = norm(pathlib.Path(chapter_fp).read_text(encoding="utf-8"))
    rpt  = pathlib.Path(report_fp).read_text(encoding="utf-8")
    quotes = [norm(q) for q in re.findall(r"^\s*>+\s*(.+)$", rpt, re.M)
              if len(norm(q)) >= 15]                      # 引用块且≥15字才算摘录
    quotes += [norm(q) for q in re.findall(r"[「“]([^”」\n]{15,})[”」]", rpt)]
    quotes = [q for q in quotes if "样张" not in q]        # 劣锚引文不算(锚来自外部文件)
    if len(quotes) < min_quotes:
        return f"冷读摘录<3处({len(quotes)})——逐项引原文作证是量规硬要求"
    miss = [q[:12] for q in quotes if q not in body]
    if miss:
        return f"冷读摘录不在正文原样存在: {miss[:3]}——报告评的不是这章(或瞎编)"
    return None
```

### 2.2 正文hash绑定(杀实验C张冠李戴+报告挪用)

冷读代理启动前,包装器把**正文首100字+末100字的sha256**写进报告头(代理无权改头部注释区);done/hook重算比对。

```python
# 生成侧(包装器,冷读代理只能填正文区):
def stamp(chapter_fp, report_fp):
    t = pathlib.Path(chapter_fp).read_text(encoding="utf-8")
    h = __import__("hashlib").sha256((t[:100] + "‖" + t[-100:]).encode()).hexdigest()[:16]
    head = f"<!-- generated-by:skill_protocol gen-coldread chapter-hash:{h} -->"
    # 替换报告头行的chapter-hash字段(仅包装器可写)
# 校验侧(done第5步/hook D0.5追加):
def hash_gate(chapter_fp, report_fp):
    h = re.search(r"chapter-hash:([0-9a-f]{16})", pathlib.Path(report_fp).read_text(encoding="utf-8"))
    if not h: return "冷读报告缺chapter-hash——须由coldread包装器产出,禁裸写"
    t = pathlib.Path(chapter_fp).read_text(encoding="utf-8")
    import hashlib
    want = hashlib.sha256((t[:100] + "‖" + t[-100:]).encode()).hexdigest()[:16]
    return None if h.group(1) == want else f"chapter-hash不符——报告评的不是本版正文(改稿后须重冷读)"
```

副作用红利: 正文改一版,hash即失效,**"改稿后旧冷读继续护航"这一隐性漂移源被同步堵死**(现门对此同样无感)。

### 2.3 出处与时序证据链(杀自我阅卷的"自证"部分)

三件最小事:
1. **冷读出处账**(新`ledgers/冷读出处.md`,进pre-commit新章硬门对账清单): 每次冷读落一行`- 第NNN章 | 日期 | 报告hash前8位 | 输入=章文件+上章末500字+锚文件清单 | 代理会话id`——由包装器写,报告无对应行=FAIL。这是"报告=代理产出"的最小证据链,虽然不能证明代理"干净",但把**声明责任**从散文变成可审计记录。
2. **commit时序**: 硬门章要求冷读报告先于(或同批)正文commit——现D0.5已隐性满足,补一条: 报告文件mtime早于正文mtime或同commit即可,禁"正文commit三天后补报告"(后补报告只配WARN)。
3. **裁判异源从声明变检查**: 技能v3已写"冷读禁用与scene-draft同款模型",但无任何记录。出处账加一列`judge-model`,done比对生成记录里的draft模型列,同款=FAIL。模型名仍自报,但**谎报会留账**,事后审计可对质。

## 三、锚定漂移: 锚是死的,裁判是活的

### 3.1 实测证据(1993书)

冷读总分序列: ch005=5 → ch010=7 → ch015=6 → ch020=7.5 → **ch025=8.5** → ch030=8 → ch031=7 → ch032=7.5。
同期三个独立信号:
- 红队-读者位(真独立视角): "文笔八分,**商业三分**",ch031给**4/10**——冷读给7;
- 漂移审计第3期: "**好消息确认循环×10轮**,钱刻度中段22章停滞,**引擎性平淡**"——定性为结构性疲态;
- quality_score(词法分): ch031=60.7,全书次低——与红队一致,与冷读相左。

即: **锚样本(白金锚/劣锚样张)自建档一字未动,冷读分却随书龄爬升,在独立证据判"最平"的中段恰好冲到峰值8.5**。两种解释——裁判真涨了,或"最近读的都比锚差"导致锚失去区分度(锚效失灵,相对打高)。**现体系无法区分这两种解释,这就是漏洞本身**。双锚校准v2有"每卷末对固定参考章复评,分数移动>2即重校"条款,但纯散文,无任何账本/门承载,查遍ledgers无复评记录——**条款存在≠条款执行**(这正是AGENTS.md批过的病)。

### 3.2 锚校准方案(一句话版)

**锚文件按卷末(约每季度)滚动加料: 白金锚由market-scan注入2-3段当季在售爆书开头摘录(锚必须和当代市场同代际,大奉/斗破是2009-2012的手感基准,不是2026年付费读者的手感基准); 劣锚轮换收入本季被打回的真实劣稿(劣锚永远是"上个月的失败",不是"去年的失败)。**

配套两件机器化:
1. **金丝雀锚(canary)**: 每10次冷读,包装器把劣锚样张伪装成被测章混入一次(报告头chapter-hash照打)。若冷读给≥7分→裁判失灵警报入`ledgers/冷读出处.md`,该裁判窗口内(自上次金丝雀以来)全部冷读分作废重评。比静态"先评锚再评章"强在: 代理不知道哪次是金丝雀,无法针对性表演。
2. **参考章复评机器化**: 每卷末对卷首章强制重冷读(hash绑定版),分数与该章首评差>2→全卷冷读标准重校+锚文件加料。落`story/audit/锚定复评-卷N.md`,进done卷末对账清单。

## 四、评审方差与双盲复评触发器

同章两独立裁判分差多少算失真: 以本库刻度(10分制、门线7、峰值线8)取**|Δ|>1.5=失真**(门线7上下1.5意味着一个放行一个打回,决策翻转);|Δ|≤0.5=收敛。单裁判分数的置信区间在LLM裁判文献里普遍±1以上,所以**单票不应直接放行硬门**。

```python
# 双盲复评触发器(done冷读步改造,伪码)
def coldread_vote(chapter, judges=2):
    scores = [run_judge(chapter, seed=s) for s in range(judges)]   # 异源/异seed,互不可见
    if all(s is None for s in scores):      return "REVIEW缺失——HALT入人审队列"
    if max(scores) - min(scores) > 1.5:     # 分差失真→第三票
        third = run_judge(chapter, seed=99)
        scores.append(third)
        if max(scores) - min(scores) > 2.0: # 三票仍散→裁判问题而非章问题
            flag_judge_window("三票分散,裁判失真——跑金丝雀锚")
            return "HALT: 裁判校准后再评,禁取均值蒙混"
    final = median(scores)                  # 偶数票取低者(商业口径从严),不取均值
    return "PASS" if final >= 7 else "REWRITE"

# 抽样策略: 普通章单票+随机20%双盲(抽中即双评); 硬门章(5倍数/卷首/峰章)必双盲;
# 连续3章单票分差(与quality_score联动)同向偏离>10 → 该窗口全量双盲复评。
```

现有"成对盲评+位置互换"只在alt-takes用,冷读单章判定是单票直判——**门线决策(≥7放行)恰恰是全链最该双盲的一票**。

## 五、漂移审计基线(evals)对"全书缓慢下移"的敏感性: 实测为零

1. **主书基线是空集**: `evals_baseline.json`(仓库根)记录于chapters:0/total_cjk:0的空库状态——pre-commit尾部的`evals.py check`(仅查主书)永远是"无回归"的**恒真命题**。
2. **在产书基线从未被自动检查**: 1993书有自己的`evals_baseline.json`(2026-09-15 07:28今晨首录,31章/均分68.0),但hook只跑`python3 tools/evals.py check`不带书根参数→**1993基线录了就再没人看**。"质量均分下滑>5"警报对真正在写的书从未运行过。
3. **首录即今晨**: 基线没有历史序列。缓慢下移的定义就是"每一步都比上一步差一点"——单一快照对它结构性失明,只能靠"基线冻结点vs现状"的巨大回看差,而重录周期全系统未定义。
4. **词法分≠读者感知**: quality_score量的是对话%/语气词/冲突词/段落形态——1993书31章词法分平稳(60-78无趋势),同期冷读、红队、漂移审计各自给出完全不同的结构性结论。**词法指标对"钩变软/笑点疲/兑现单调"这类读者侧漂移不敏感**,而恰好冷读分序列(最该进基线的读者侧信号)不在evals任何一处。

**方案**: evals基线双层化——**冻结层**(立项后首卷末录,永不重录,管"相对开书时的水位")与**滚动层**(每卷末重录,管"相对上一卷的缓变",任一项较上卷恶化>10%=回归);冷读总分序列+锚定复评分作为`reader_scores`字段入基线;pre-commit的evals检查改为遍历所有书根(`for b in books: evals.py check <b>`),杀掉恒真空转。
