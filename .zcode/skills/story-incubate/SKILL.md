# Skill: story-incubate
# story-incubate:故事孵化（构思域第0步·先于premise）

> 溯源：用户核心洞察——"写作前需要投入80%的精力去构思"
> 白金作家实况：唐家三少构思用数月反复推翻，猫腻想清楚"为什么值得写"才动笔
> 本技能是构思域的**第0步**，在premise之前运行

## ⛔ 核心理念

**不是"填一个正确的前提句"，而是"找到一个非写不可的故事"。**

```
错误流程（我们目前的做法）：
想法 → 30分钟写前提句 → 过闸 → 下一步

正确流程（白金作家的做法）：
想法 → 孵化（数天到数周）→ 多轮推翻重构 → 
试写验证 → 再推翻 → 最终确认"就是这个" → 才开始正式立项
```

## 孵化五法

### 法1：极端推演（"如果...会怎样"×20）
把核心创意推到极限，看故事在极端情况下是否还成立。

```
以"能看见因果债契的账房学徒"为例：

如果他能看见自己的债呢？→ 发现自己是别人计划的一部分
如果他看不见任何债呢？→ 他的力量在什么情况下失效？
如果全世界都能看见债呢？→ 他的独特性在哪？
如果他讨厌自己的能力呢？→ 想摆脱而非利用
如果他遇到一个完全无债的人呢？→ 这个人是谁？为什么干净？
如果他爱上一个他看得见其巨债的人呢？→ 感情与能力的冲突
如果他的能力是遗传的呢？→ 家族秘密
如果债契是活的呢？→ 债有自己的意志
如果有人能伪造债契呢？→ 能力不可靠
如果他的能力在杀死他呢？→ 每用一次代价

...至少推演20个极端场景，每个至少100字的展开
```

### 法2：角色对话（在写大纲之前"采访"角色）
不填人物表。直接写角色之间的对话，让他们自己说话。

```
写一段500字的对话：
主角和他最重要的人（师父/父亲/挚友）

不看任何设定，就凭"感觉"写。
写完后问自己：
- 这个人的说话方式让我意外吗？（意外=角色活了）
- 我预测得到他下一句会说什么吗？（预测不到=活的）
- 我想让读者记住他的哪句话？

如果全程都在预测之内 → 角色没活，继续孵化
```

### 法3：杀主角测试
如果主角在第1章就死了，故事还能讲吗？

```
以本书为例：陈更第1章死了
→ 谁会接手他的悬账？为什么？
→ 那个人接手后会做出什么不同的选择？
→ 那个版本的故事更有趣吗？

如果"没有主角的故事"比"有主角的"更有趣 → 你的主角选错了
```

### 法4：一句话电梯测试
给一个完全不看网文的朋友讲这个故事（30秒），看他的反应。

```
"有个人能看见所有人欠的债，他去替死人讨债。"

朋友反应：
- "哦" → 故事不够抓人，继续孵化
- "然后呢？" → 有钩子但不够深
- "卧槽那他自己欠不欠？" → 钩子成立，且朋友自己发现了深层问题

如果讲完对方没有任何追问 → 这个故事还不值得写
```

### 法5：类型转换测试
如果把设定搬到完全不同的类型，核心还成立吗？

```
"能看见债"搬到：
- 现代都市 → 律师/审计/金融？
- 科幻 → AI信用系统？
- 武侠 → 江湖恩怨簿？
- 悬疑 → 连环杀手留下"债"标记？

核心是什么？是"看见隐藏的关系"。
如果核心在类型转换后依然有力 → 故事的骨头是硬的
如果转换后就没意思了 → 你依赖的是设定而非故事
```

## 孵化产物

孵化不产出正式文档。产出的是：
1. **极端推演清单**（20+个"如果...会怎样"及展开）
2. **角色对话样本**（至少2组，每组500字）
3. **杀主角测试记录**
4. **电梯测试反馈**
5. **类型转换笔记**
6. **一页"非写不可"宣言**——为什么必须是这个故事？为什么必须是我写？

这些产物存入 `story/00a-孵化/`（注意：是00a，排在00-前提之前）

## 过闸标准

孵化不能"自我宣称完成"。必须通过以下检验：

1. **极端推演**：至少20个场景，每个有100字展开
2. **角色对话**：至少2组对话让自己意外
3. **杀主角**：测试记录+结论
4. **电梯测试**：至少一个追问
5. **宣言**：能用一段话回答"为什么非写不可"

全部通过 → 调用 premise 开始正式立项
任一不过 → 继续孵化，不许进入下一步

## 与其他技能的关系

- **premise**：孵化完成后才开始（孵化是premise的前置）
- **ideate**：路由表中将本技能排在最前
- **author-persona**：孵化过程中同步生成作者人格

## evals

- "我有个想法你听听" → 走完整孵化五法
- "这个想法行不行" → 走法4电梯测试+法3杀主角
- "构思卡住了" → 走法1极端推演，推20个场景
