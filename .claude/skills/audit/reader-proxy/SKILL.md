# reader-proxy:读者代理冷读

> 溯源:docs/26(量规/锚定/判定规则)·迭代31实战。产物:`text/审/第X章-冷读.md`。

## 前置条件

chapter-assemble 已过卫生(check.py全绿)。不净之稿不冷读(浪费代理)。

## 流程

**1 组装代理(每次新开,零项目上下文)**
1.1 指令:起点十年毒舌读者人设+只给两个文件:本章全文+上一章末500字;
1.2 **锚定校准**(冷启动:无历史劣稿时,以风格包盲评记录中最低分稿造锚):同时给一份"已知差锚"(本项目历史劣稿样张,存 `story/50-风格包.md` 附录或指定文件)令其先评——若代理给劣锚打高分,本轮全部结论弃用重开(裁判失真防线)。

**1.5 信号路由(读者说的不是诊断)**:五通道映射——代入感差查视角与心理距离/无聊查社会模拟(人物关系网)/审美差查语言/不好奇查悬念与信息差/心流断查节奏密度。信体验不信自我归因,双源收敛才高置信。

**2 六项冷读量规(笑/跳/爽/追读/硬特征/成对;非docs/08神作六维)(要求逐项引原文作证,禁空评)**
①笑点数(实际笑/会心几次,各在第几段);②跳读点(引原句,标时长);③爽点兑现(一句话说出本章"得到"什么,说不出=无);④追读欲(章末点不点下一章,为什么,钩强度1-10);⑤AI感硬特征(原样重复/警句堆叠/解说笑点/情绪标注/段尾总结腔,逐项查);⑥成对比较(与上一章比,更想读哪章)。

**3 判定(硬线)**
喜剧主档章笑点<2 → 重写;跳读>2处或单处>3行 → 重写该场景;AI感硬特征任一命中 → 修;追读欲"无所谓" → 钩失效,回场景卡重排钩。
无硬线但六维平庸 → 标黄;连续两章标黄 → **暂停推进**,回风格包再校准(调性漂移警报)。

**4 回路**
4.1 结论落盘;重写走 `revise:scene-rewrite`(整场景重生成);
4.2 通过 → `NEXT-SKILL: ops:ledger-update`。

## 类型配置声明

本技能默认值(笑点审计/爽点兑现/喜剧硬线)针对**喜剧向男频**。跨类型项目须在立项时替换:硬科幻→笑点换惊奇/恐怖→笑点换寒点(悬念维持)/言情→笑点换甜度。**默认值是参数不是真理**。同理:drift-audit的笑点密度指标、pacing-score的喜燃泪档位、gates.py的感情线必过件——均为可替换的类型配置。
