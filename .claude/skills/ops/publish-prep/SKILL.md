# publish-prep:发布准备(ops域)

> 溯源:docs/17(D16/D17/D18发布策略与数据锚)·26(文案工艺)。产物:`ledgers/发布检查单.md`。

## 前置条件

开篇弧过审+存稿在累积中(本技能是发布前30天的滚动检查)。

## 流程(检查单式,逐项状态)

**1 存稿与节奏**
- [ ] 存稿≥6万字(卡签约吃满新书榜30天);
- [ ] 签约后5日内可更满2万字(触发新书入库;断更即失格——红线);
- [ ] 日更产能实测:日产下限4000字×2章,可持续两周验证过;
- [ ] 断更预案:三存一(每写三章存一章不发的缓冲)。

**2 时机**
- [ ] 上架窗口:20-30万字申请入V,避开新书榜期结束前上V(不透支流量);
- [ ] 上架前一章=强钩章(首订最大化);上架爆发章预写完。

**3 文案终审材料(交用户,不自行定稿)**
- [ ] 书名三案(书城并排3秒测试);
- [ ] 简介两案(第一句钩→双承诺→门槛信号);
- [ ] 平台AI政策核对(封代笔不封辅助/官方指定工具/声明要求);
- [ ] 分类与标签(主分类+引流标签,docs/16);
- [ ] 章节名规范(禁剧透钩子/风格统一)。

**4 数据锚(发布后对照用)**
- [ ] 记录目标线:首订1000及格/3000精品(docs/17);每卷末对照实际数据回写本检查单。

## 上架与运营(红队J2/K2:2026.2新四轮PK机制下的现行规则)

- **上架时机=真追函数,不是固定字数**:真追<100→30万字上架;100-300→20万;>300→10-15万。自诊:收订比10:1-15:1(优秀5:1);
- **上架日三件套**:排月底保全勤+当天爆更8000-10000字+付费墙切在大冲突上升段前一章;
- **推荐机制时间线**(2026.2.8现行):新书入库(签约+5天稳定更新+2万字→10天保底流量)→四轮PK晋级链→三江/强推→智能推10万字入场;断更重新排队,推荐间隔≥25天;
- **存稿双轨制**:公开期≤10章+上架前10-15章爆发稿;
- **断更代价**:300-450元/天损失、LV4追订腰斩、掉榜恶性循环——**请假优于断更**;
- **月票运营**:作者福利月票是唯一自控票仓(日更4000字=6张/本章说10张/彩蛋章20张,上限186+40);**月初大高潮领跑月票榜**(玄鉴仙族/大奉实证);
- **净网敏感期**(4-10月)避开上架窗口;
- **长跑纪律**:均质>爆发(唐家三少7000-8000字×86月不断更>脉冲式);细纲领先30章;卡文走SOP不许硬写。

## 完本长尾(红队K2)

- 完结后1-2个月是"养肥党"涌入的第二波数据窗口;完本榜=长青IP池入口;
- 系列化两模式:世代续作制(斗罗)vs角色宇宙制(盗笔)——立项时选;
- **留口不挖坑**:完本可以留开放线头,不许留未兑现承诺;
- 太监标签跟人不跟书(伤及下一本书)——**太监是态度问题>烂尾是能力问题**。

## AI检测红线（2026-09-12调研,详见story/audit/工艺深研-AI检测平台红线.md）
- 红线: 纯AI正文=拒签/下架/封号(起点单月处置100本均订过万AI书,全网下架2.8万部);2026-04起点《非真人自动化创作管理公告》分级处罚(限流→撤榜→屏蔽→下架→解约→封号)。
- 检测原理: 困惑度+突发性(句长波动——check.py#9已监控)+词频熵+连接词模式;番茄同章AI率可在0-87%间波动(误判存在,可申诉)。
- 过检实操: ①朱雀定位高AI率段落定点重写(禁全篇通改) ②提突发性(长短句混排) ③洗标准化连接词 ④改写分段≤1000字防越改越AI ⑤保≥30%人工深度修改+主动声明(起点允许AI查资料/灵感/大纲)。
- 本系统对应: de-ai技能+check.py句长方差#9+段落方差#13+人工冷读=合规生产线;发布前全书过朱雀抽测留档。

## 上架章设计（红队20260919商业批:首V=全书最重要商业节点,"预写完"不回答"怎么写"）

- **免费末章**: 收在全书前30%最强钩之一(冲突引爆前夜,禁在本章内引爆——引爆=读者看完爽点就不付费);免费期重钩率×1.5(pacing-score双档);
- **首V章(上架第一章)**: 三拍结构——接免费末章钩(读者钱花在"马上要知道"处)→本章内小兑现(证明付费值)→末尾更大钩(证明下章还得看);
- **上架三连爆排期**: 首V日爆更8000-10000字=3-4章连发(按卡带拼章,走duanzhang切割不禁多章同发);第2-3日各一次中爆点;首周钩密度维持免费期档;
- **卡点排期**: 卷纲预标"商业位"(volume-outline预标),付费墙切在冲突上升段前一章末。

## 章末运营件（红队20260919商业批:每天产章,却不产自控流量入口）

- **作者的话三段式**(≤120字): ①下一章预告一句(钩的复述,禁剧透反转) ②求票位(月票/推荐票,有彩蛋才提) ③互动议题(问读者一个本章内的问题,拉评论);
- **防剧透回复纪律**: 回复评论只引已发内容,下章反转/伏笔一律"看了下一章你就知道";差评不对线,引原文自证或置之;
- **彩蛋章工艺**: 月票目标达成加更1章,内容=正文中删掉的高光段+作者批注(成本最低的加更)。

## 月票冲刺排期（红队20260919商业批:大高潮对齐日历,排纲时不看日历=白排）

- 卷末大高潮章对齐月初1-5日(月票榜领跑窗口);volume-outline排纲时倒推:高潮章号-今日/日更速度=上架/冲刺日期;
- 冲刺周加更计划:从存稿双轨的"运营轨"出(保更轨禁动);加更章优先发高潮后余波章(写作难度低+读者情绪高);
- 数据对表:每月1日填ledgers/数据账.md(章号|追读/均订/首订|日期),环比跌>15%→回注pacing-score复排当卷;首订1000及格/3000精品,预警线:均订连续2月环比跌>15%=流派引擎复查(genre-playbook死因库)。

## 发布进度账（存稿红灯的数据源,pipeline status每跑必读）

`ledgers/发布进度.md` 一行格式: `已发至: 第NNN章 (YYYY-MM-DD)`——每次平台发布后更新;商业计划.md须有`日更: N`行,pipeline按`已写-已发`折算存稿天数红灯(<3天=断更临界,<7天=WARN)。

## 内容合规终检（红队20260919十波批W9:合规层全库空白）

上架前逐项过一遍(平台规则会变,以当日平台公约为准):
1. **敏感内容分级**: 暴力(过程细节≤2句,禁器官级)/涉政(架空化,禁现实事件与在世人物)/性(全隐,关系止于门槛外)/宗教民俗(架空化,禁仪式细节);
2. **平台违禁词**: 用平台后台自检工具+人工抽查高危章;正文禁词与AI腔禁词(docs/20)是两回事;
3. **版权红线**: 歌词/诗句引用≤2句且须公版(作者逝世超50年),现代歌名可提禁引词;
4. **专业细节**: 医疗/法律/金融情节,关键细节用"模糊具体法"(说结果不说操作),禁可模仿的危险细节;
5. 记入发布检查单,任一项不过=延迟上架。
